# Team Hub 桌面端交互规范

## 布局与层级

- 沿用同级页面的内容宽度、边距、卡片样式和文字层级。同一行有多个动作时，主要操作优先，编辑、下载等常用动作保持可见，删除采用危险操作样式。
- 列表分组用标题显示分类与数量。默认展开，标题可点击收起。未分类放在最后，空列表说明当前状态。
- 窗口变窄或放大页面时，表单和行内按钮可换行。关键内容、焦点和操作按钮应能进入可视区。

## 弹窗与表单

- 编辑、确认等短流程使用模态弹窗，在浏览器内容区水平、垂直居中。原生 dialog 显式设置定位和自动外边距，检查全局 CSS 重置后的计算样式。
- 弹窗与视口四边至少留 16px。空间不足时弹窗内部可滚动，确认和取消始终可以滚动到。
- 打开编辑弹窗时预填当前值，焦点落在首个可编辑字段。支持 Tab 和 Shift+Tab 在弹窗内移动。取消和 Esc 放弃未保存修改，关闭后焦点回到触发按钮或更新后的对应行。
- 字段标签放在输入框上方，必填、可选和格式要求靠近字段。分类支持输入新值、选择已有值和清空。
- 保存和取消放在底部右侧，保存时防重复提交。失败时保留输入并显示可操作的错误，成功后让列表显示新值。删除前显示具体对象并二次确认。

## 发布前验收

- 至少在 Chrome 测一次真实页面入口。弹窗用常规窗口和较窄窗口各打开一次，检查居中、遮罩、边距和内部滚动。必要时加测 Safari。
- 验证键盘焦点、Esc 取消、空值、保存成功、保存失败和行更新。用测试数据验证写入。
- 涉及 CSS 或脚本变更时更新相应资源版本。发布后核对线上资源，条件允许时再从页面入口走一次操作。
